## Executive Summary

An investigation was conducted into the four pending corroboration candidates reported in `.geopulse/pilot_queue.json` sharing identical synthetic payloads:
- **Title**: `Intercepted Naval Operation`
- **Claim**: `Naval patrol started.`
- **Evidence**: `patrols began`
- **Publishers**: `Outlet A` and `Outlet B`
- **URLs**: `https://a.com/1` and `https://b.com/2`

### Key Findings
1. **Root Cause**: The records were **not** generated by the real-world ingestion, clustering, or summarization pipelines. They were written to `.geopulse/pilot_queue.json` as a side-effect of running the unit test suite (`tests/unit/test_pilot_workflow.py`).
2. **Mechanism of Leakage**: Specifically, `test_cli_brief_pilot_supervision_interception_alert` calls the CLI entry point `main(["brief", "--fixture", "--mock-model", "--pilot-supervision"])`. Inside `handle_brief`, `OperatorSupervisedPilot()` is instantiated with default arguments, resolving to the workspace file `.geopulse/pilot_queue.json`. Because the test did not isolate the pilot storage path or monkeypatch the pilot engine, the mock event was persisted directly to disk.
3. **Multiplicity (4 Instances)**: The test creates a new `EventCluster` on each invocation, generating a fresh random `uuid4()` for `event.id`. Consequently, each execution of `pytest` appended an additional entry rather than overwriting the previous one. The four timestamps match the exact moments when test suites were run on November 5, 2026.
4. **Impact on Briefings**: **Zero**. The real briefing generator does not consume candidates from `pilot_queue.json`. Published briefings, previews, and Telegram payloads were unaffected.
5. **Operational Safety**: The pilot review queue is **currently contaminated and unsafe for operational decision-making** because running `geopulse pilot queue --status pending` presents human analysts with 100% synthetic test artifacts rather than genuine intelligence candidates.

## 3. Storage Persistence & Failure Mechanism

### Default Storage Paths in `pilot.py`
In `src/geopulse/pilot.py`:
```python
class OperatorSupervisedPilot:
    def __init__(
        self,
        log_path: Path | str | None = None,
        queue_path: Path | str | None = None,
        formatter: TelegramDigestFormatter | None = None,
    ) -> None:
        self.log_path = Path(log_path or ".geopulse/pilot_review_log.json")
        default_queue = (
            self.log_path.parent / "pilot_queue.json" if log_path else ".geopulse/pilot_queue.json"
        )
        self.queue_path = Path(queue_path or default_queue)
```
When instantiated without arguments, `self.queue_path` defaults to `.geopulse/pilot_queue.json` relative to the current working directory.

### Isolation Discrepancy Between Unit Tests
In `tests/unit/test_pilot_workflow.py`:
- Tests 1 through 6 properly isolate storage by passing `log_path=tmp_path / "pilot_log.json"`, causing `default_queue` to resolve inside pytest's temporary directory.
- Test 8 (`test_cli_brief_pilot_supervision_interception_alert`), however, tests the CLI command directly:
```python
def test_cli_brief_pilot_supervision_interception_alert(capsys, monkeypatch):
    ...
    exit_code = main(["brief", "--fixture", "--mock-model", "--pilot-supervision"])
```
In `src/geopulse/cli.py` (`handle_brief`):
```python
if getattr(args, "pilot_supervision", False):
    from geopulse.pilot import OperatorSupervisedPilot

    pilot = OperatorSupervisedPilot()  # <--- Defaults to .geopulse/pilot_queue.json!
    results, pending_packets = pilot.supervise_summaries(results, hold_unapproved=True)
```
1. `handle_brief` does not accept `--queue-file` or `--log-file`.
2. `test_cli_brief_pilot_supervision_interception_alert` did not mock `OperatorSupervisedPilot` or provide an isolated environment/path.
3. When `pilot.supervise_summaries(...)` ran, it intercepted the mock event and called `self._persist_queue_items(all_candidate_packets, summaries_by_id)`.
4. `_persist_queue_items` loaded the live `.geopulse/pilot_queue.json`, merged the test packet keyed by `pkt.event_id`, and wrote the file back to disk.

## 5. Duplicate Packets vs. Distinct Events

Analysis of the four records proves they are **duplicate artifacts of the same test scenario**:
- The event title, headline, narrative text, category, claims, evidence spans, and source lineages are bit-for-bit identical.
- The only differences are:
  1. `event_id`: Each test run generated a new `uuid4()` via `EventCluster.__init__`.
  2. `candidate_fingerprint`: Because `compute_candidate_fingerprint` incorporates `event.id`, the resulting SHA-256 hash changed on each run.
  3. `enqueued_at` / `generated_at`: The system clock at test execution time.
- Because `_persist_queue_items` maintains a dictionary keyed by `item["event_id"]`, the 4 test runs did not overwrite one another; each added another duplicate record.

## 7. Safety Assessment & Recommended Resolution

### Operational Safety Assessment
- **Briefing Delivery**: **SAFE**. The delivery engine (`handle_brief`) constructs briefings from live clustered articles and only applies pilot supervision as an outgoing filter. It never reads or publishes from `pilot_queue.json`.
- **Operator Review Queue**: **UNSAFE**. Running `geopulse pilot queue --status pending` currently displays four synthetic test records as high-priority corroboration candidates requiring analyst action. This corrupts analyst audit logs and pilot evaluation metrics.

### Recommended Smallest Fix (For Future Implementation)
1. **Test Isolation (`tests/unit/test_pilot_workflow.py`)**:
   Update `test_cli_brief_pilot_supervision_interception_alert` to isolate its storage paths using `monkeypatch` or `tmp_path`, ensuring that test executions never write to `.geopulse/pilot_queue.json`.
2. **CLI Configuration (`src/geopulse/cli.py`)**:
   Add `--queue-file` and `--log-file` arguments to `brief_parser` and propagate them to `OperatorSupervisedPilot(queue_path=..., log_path=...)` inside `handle_brief`.
3. **Queue Sanitization**:
   Safely remove the four synthetic UUIDs (`11248b3a-0dd8-4adc-a67a-fb2b47478966`, `1ad52a2d-42d5-40f6-ab12-e655be63d3e5`, `4a585f62-7c65-43ae-bea7-00be16ac77bc`, `1128236b-2c4d-4128-8c1f-ccff12bb0915`) from `.geopulse/pilot_queue.json`.
